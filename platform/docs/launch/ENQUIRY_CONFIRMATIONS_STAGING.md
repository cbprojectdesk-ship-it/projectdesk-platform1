# Enquiry acknowledgements — staged test support

The fixed-business-inbox enquiry path remains unchanged when the new flag is absent. Optional `CCS_WEBSITE_CONFIRMATIONS=test` enables a separate acknowledgement **only** if the validated enquirer address is already in `QUENVIRA_EMAIL_TEST_RECIPIENTS`. Any other flag, including `live`, never enables arbitrary-recipient mail. No runtime configuration was changed and no message sent by this development.

The acknowledgement contains fixed CCS wording and a validated enquiry reference, not reflected enquiry text, customer names, quoted prices, links chosen by the visitor or attachments. It is visibly marked test, replies to the fixed business inbox, and explicitly confirms submission rather than a contract/subscription. Business-inbox success is persisted before acknowledgement. Separate stable provider idempotency keys, conditional request claims and durable accepted/pending/unconfirmed receipts prevent duplicate sends. A duplicate submission reads the receipt; it cannot restart either delivery. A failed/ambiguous acknowledgement does not turn a received business enquiry into a failure requiring resubmission. Provider acceptance is reported as `accepted`, never `delivered`.

The quota reserves **provider attempts**, not just enquiries: the existing five-per-UTC-day contact allowance charges two units before an acknowledgement-enabled enquiry, one otherwise. Its two-per-client/day cap remains. Thus the old contact transport budget is preserved alongside the invoice dispatch rolling-24-hour cap; adding acknowledgements cannot double provider allowance usage. Metadata stores hashes/references/state/provider IDs only. Signed contact-tag callbacks remain isolated from invoice tables.

Local acceptance covers explicit flag/allowlist gates, separate keys, duplicate submits, provider ambiguity, business failure, quota exhaustion, concurrent requests and lost final receipt writes. Actual test-recipient inbox receipt and production publication remain unverified. Before arbitrary customer acknowledgements, implement a separately approved production recipient/suppression policy, validate sender/provider quota and deliverability, update website success messaging for receipt state, and conduct isolated hosted acceptance. Do not set a live flag or reuse invoice live-sending approval as contact-mail approval.
