# Quenvira source and workflow audit — 20 October 2026

Status: private development candidate. This record covers local source, API/database and client-adapter verification, not completed live-browser or commercial acceptance.

## Defects reproduced and corrected

1. **Form submissions lost their values.** Busy-state handling disabled inputs before constructing FormData. Disabled controls are excluded from browser form data. The improved adapter reproduced three failing client tests before the handler was corrected to collect values first. Submitted forms now pass the actual client-handler/API/SQLite lifecycle checks. Busy state is also reapplied after rerender and workspace switching is serialised.
2. **Revoked access could be restored with another invitation.** Revoking access now invalidates all invitations for the same staff record and account email, and removes associated membership. Other staff/account invitations are not revoked.
3. **Permission changes during writes were not enforced at commit.** Workspace commands now condition their transactional writes/history on current matching membership. Invitation creation/revocation and workspace deletion also check manager authority within the transaction. Tests cover revocation/demotion between initial authorisation and the commit.
4. **Reused operation IDs could hide a different command.** New operation records include a request hash; a mismatched replay is rejected. Existing pre-hash records retain compatibility. The internal hash is not returned in replay responses.
5. **Calendar navigation could leave the supported year range.** Invalid dates and out-of-range navigation produce a controlled error; a week near the last supported date is bounded. Date inputs declare the supported year limits.
6. **Invitation quota was vulnerable to concurrent creation.** The pending-invitation limit is now checked in the insertion transaction as well as before it.

## Recurring visit controls added

Managers can pause, resume, cancel or change pending visits from a selected future recurring visit. Editing shifts the dates together while preserving visit IDs, spacing, customer, recurrence label, notes, checklists and paused status. Earlier, completed, in-progress and already cancelled records are not changed.

Paused visits reserve no staff capacity and cannot be started. Resuming checks every destination for overlaps and daily capacity. Future edits and resumes are all-or-nothing, including conflicts or calendar overflow in a later visit. The API still enforces manager/tenant access, revision checks and idempotency. A single visit can also be edited or cancelled without changing the remaining series.

Recurrence is still a finite batch of at most twelve booked visits; these changes do not add an endless background generator or multiple workers per visit.

## Deployment and rollback caution

The new Paused status is accepted by the updated server validator. Once data contains it, reverting to the old validator would reject that workspace. Before deployment, test forward-compatible rollback code or a carefully controlled restoration plan; do not blindly roll back the server binary after allowing paused data. No database schema migration is needed for these JSON document changes.
